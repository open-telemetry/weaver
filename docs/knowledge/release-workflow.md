# Release Workflow

`.github/workflows/release.yml` is generated by
[cargo-dist](https://github.com/axodotdev/cargo-dist) from `dist-workspace.toml`,
then hand-edited to fix Scorecard and zizmor findings.
`allow-dirty = ["ci"]` in `dist-workspace.toml` stops `dist generate` from
overwriting those edits, so an upgrade regenerates the file and merges the edits
back.

Where dist supports it, keep a fix in config instead of in the workflow: action
pins go in `[dist.github-action-commits]` (format
`"owner/action" = "<sha>" # vX.Y.Z`, which Renovate updates), and build setup
steps go in `.github/build-setup.yml`. Config-based fixes survive regeneration.

## Hand edits

Each edit fixes a Scorecard or zizmor finding. Keep all of them when you
regenerate.

| Edit | Why |
| --- | --- |
| Top-level `permissions: contents: read` | Scorecard Token-Permissions. dist generates `write`. |
| `host` job gets `contents: write` | `gh release create` needs it. Scorecard flags any job-level write, so that alert is dismissed, not fixed. |
| `plan` job has no `permissions` | `dist plan` and `dist host --steps=create` make no GitHub API writes for GitHub hosting, so the job inherits `read`. |
| Install dist: download to `/tmp`, `sha256sum -c`, then `sh` | Scorecard Pinned-Dependencies. dist generates `curl \| sh`. |
| rustup in containers: the same download, verify, execute | Scorecard Pinned-Dependencies. |
| `${{ }}` in `run:` moved to `env:` (`DIST_PLAN_ARGS`, `DIST_ARGS`, `TAG_FLAG`, `NEEDS_PLAN_OUTPUTS_TAG_FLAG`, `NEEDS_PLAN_OUTPUTS_TAG`) | zizmor template-injection. "Build artifacts" also gets `shell: bash`. |
| `# zizmor: ignore[...]` on `container:`, `run: ${{ matrix.install_dist.run }}` and the `${{ matrix.packages_install }}` step | dist emits these from its run-scoped plan, so they cannot move to `env:`. |
| `custom-smoke-test-installers` also needs `build-global-artifacts` | The smoke test needs the global installers. |
| `custom-smoke-test-installers` has no `secrets: inherit` | It uses no secrets. |

These are generated from config, not hand edits: the `actions/attest` SHA pin
(`[dist.github-action-commits]`) and `package-manager-cache: false` on
setup-node (`.github/build-setup.yml`, for zizmor cache-poisoning). If a later
dist release generates an edit in the table, remove it from the table.

## Upgrading cargo-dist

Renovate's cargo-dist PRs fail in the `plan` job, because Renovate bumps the
installer URL but not its sha256. Do the upgrade on a branch from `main`, and
close the Renovate PR from your PR.

1. **Read the release notes** for each version between the current
   `cargo-dist-version` and the target
   (`gh release view vX.Y.Z --repo axodotdev/cargo-dist`). Look for template
   changes, security changes and installer behaviour changes.
2. **Install the target version** next to the current one, for example
   `cargo install cargo-dist --version X.Y.Z --locked --root <dir>`. You need
   both versions.
3. **Make the merge base.** Save a copy of `release.yml`. Delete the
   `allow-dirty` line (keep its comment), run `dist generate --mode ci` with the
   **current** version, save the output as the base, and restore with
   `git checkout .github dist-workspace.toml`. A diff from the base to the saved
   copy must show only the hand edits above. Anything else means the base is
   wrong.
4. **Generate with the new version.** Set `cargo-dist-version`, delete the
   `allow-dirty` line again, and run `dist generate --mode ci` with the **new**
   version. Diff it against the base to see the upstream changes. Treat a
   surprising change as intentional until the upstream commit history for
   `cargo-dist/templates/ci/github/release.yml.j2` says otherwise.
5. **Merge** the saved copy onto the new output:
   `git merge-file -L hand -L base -L new <saved copy> <base> <new output>`.
   Resolve each conflict by keeping the hand edit's structure with the new
   upstream values, and copy the result to `release.yml`.
6. **Update the pins** (below).
7. **Restore `allow-dirty = ["ci"]`** under its comment.
8. **Check:**
   - The diff of `release.yml` against `main` shows only the version bump, the
     new pins and the upstream changes from step 4.
   - `dist plan --output-format=json` succeeds with the new version. Compare the
     runners in `ci.github.artifacts_matrix` with the old version's plan, and
     call out any change in the PR.
   - The YAML parses, and every hand edit in the table is present.
   - zizmor and Scorecard pass on the PR. Open code-scanning alerts are at
     `gh api "repos/open-telemetry/weaver/code-scanning/alerts?state=open"`.

## Pins

- **dist installer.** Download
  `https://github.com/axodotdev/cargo-dist/releases/download/vX.Y.Z/cargo-dist-installer.sh`
  and take its sha256. Do the same for the current version first, and confirm
  that it reproduces the existing pin. The installer has no GitHub attestation,
  so also confirm that the checksum it contains for
  `cargo-dist-x86_64-unknown-linux-gnu.tar.xz` matches that release asset.
- **rustup-init.** `sh.rustup.rs` always serves the latest script, so this pin
  goes stale with each rustup release. Read the version from the
  `rustup-init X.Y.Z` line in the script. Confirm the script is identical to
  `rustup-init.sh` at that tag in `rust-lang/rustup` before you pin its sha256.
